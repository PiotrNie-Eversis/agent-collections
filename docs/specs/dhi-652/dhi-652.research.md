## Gap Analysis

### Question 1
#### README.md's "Related documentation" table has 12 rows, but only 7 map onto the docs site's 4 clusters — the other 5 (`AGENTS.md`, `documentation/agent-collection.md`, `docs/architecture/requirements-traceability.md`, `mcp/eversis-collections-mcp/README.md`, `CHANGELOG.md`) are repo-internal files with no equivalent cluster. Should the plan (a) add a 5th group, e.g. "In this repository," for these non-website-docs rows, (b) drop them from this table and let them stay wherever else they're already linked in the README (they are — e.g. `CHANGELOG.md` is also linked from the Versioning section), or (c) something else?

**Resolved during research** (not escalated — a reasonable default, not a scope-changing ambiguity): **Option (a)**. A 5th "In this repository" group keeps every current row reachable (no silent removal, satisfying the "no content loss" precedent set by DHI-642) while still giving the table the same visual grouping benefit the AC asks for. This mirrors the docs site's own pattern of having exactly one landing section per real category rather than forcing unrelated content into an existing cluster.
