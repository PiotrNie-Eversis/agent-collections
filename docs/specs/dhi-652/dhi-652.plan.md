## Wildly Important Goal

**Goal**: `README.md`'s first-screen framing and its documentation table read consistently with the docs site's already-restructured intent-based IA, so the README isn't a step backward in clarity from the site it links to.

**Success Measure**: `README.md`'s opening leads with a plain-language sentence before any jargon term (vendor-neutral / multi-agent / adapters / MCP), and the "Related documentation" table is organized into 5 labeled groups instead of one flat 12-row list, with every currently-linked resource still reachable.

**Do NOT touch**: Any file other than `README.md`; the docs site itself (`website/docs/**` — already correct, read-only reference for this task); no new components or code; no removal of any of the 12 currently-linked resources.

## Proposed Solution

Two content edits to `README.md`, both additive/reorganizing, no information loss:

1. **Opening rewrite** — add a plain-language problem/fix lead sentence before the existing "vendor-neutral multi-agent..." paragraph, mirroring the exact move `website/docs/intro.md` made under DHI-645 (jargon paragraph kept, just demoted to second position, framed as "under the hood").
2. **Related documentation regroup** — split the current flat 12-row table into 5 labeled groups: the same 4 clusters the docs site uses (**Getting Started**, **The Main Flow**, **Reference**, **Advanced / CTO**), plus a 5th **In this repository** group for the 5 rows that aren't `website/docs/**` pages (`AGENTS.md`, `documentation/agent-collection.md`, the architecture doc, the MCP package README, `CHANGELOG.md`) — per the research's resolved Question 1.

No diagrams needed — this is a two-edit content change to one file.

**Files:** `README.md` (modify)

**Definition of Done**:

- [ ] The "Related documentation" section contains exactly 5 group headers: Getting Started, The Main Flow, Reference, Advanced / CTO, In this repository
- [ ] All 12 link targets present in the original table (`./website/docs/getting-started/start-here.md`, `prerequisites.md`, `installation.md`, `mcp-setup.md`, `quick-wins.md`, `./website/docs/advanced/migration-from-cursor-collections.md`, `./website/docs/main-flow/workflow/overview.md`, `./AGENTS.md`, `./documentation/agent-collection.md`, `./docs/architecture/requirements-traceability.md`, `./mcp/eversis-collections-mcp/README.md`, `./CHANGELOG.md`) still appear somewhere in the regrouped section — verify via `grep -c` for each target against the pre-edit and post-edit file, counts must match
