**User story:** As a consumer project owner, I want a documented way to upgrade from the central `agent-collections` framework so that improvements propagate without re-installing from scratch.

## Business Impact

Closes WNF-02 (“upgrade without wiping project-owned files”) at the **contract** layer before DHI-537 delivers a tested consumer upgrade path with the installer. Enables consistent release tags, changelog migration notes, and safe pinning via submodule / tag / future `--version`.

## Acceptance Criteria (from Jira)

1. Consumer on version N → when N+1 is published, a **documented** upgrade path exists (sync, submodule bump, **or** CLI upgrade)
2. When the upgrade contract is applied, **project-owned** files (e.g. project stack, local context) are **never overwritten** without **explicit opt-in**
3. When a breaking change is released, it is **noted in the framework changelog** with migration steps
4. Inherited SDD AC (spec folder, research → plan → implement → review → Fine)
