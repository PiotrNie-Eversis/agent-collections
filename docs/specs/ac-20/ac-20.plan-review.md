## BLOCKERS

### B1: The page update never says which tickets change `docs/context/<project>/INDEX.md`

Question 18 requires four "already shipped" sentences and an untouched add-a-fact section. Task 1.1's Definition of Done checks those four topics and forbids an enum, keys, and a decisions how-to. It does not check the project index.

Live page (`website/docs/reference/domain-context.md`): the read section names `docs/context/<project>/INDEX.md`. The write loop and the "What to use" table send promote, add-a-fact, import, and audit to `docs/context/<project>/` and never say the index row is added or changed.

Child plans, already resolved:

- AC-22 writes the component file and the `INDEX.md` row when the summary is new or changed.
- AC-18 keeps the table at two columns, stores the audit count in `INDEX.md` frontmatter, and increments that count at Fine even when promotion writes nothing. It left the website to AC-20.
- AC-16 reads and writes `docs/decisions/INDEX.md` and forbids a decision column on the project index.
- AC-17 and AC-19 do not write the project index. AC-17 already updated `overview.md` and told AC-20 to mention As-Is on `domain-context.md`. AC-19 told AC-20 to fix the "exact four-line" pages.

An implementor can satisfy every checkbox in this plan and still leave a reader unable to tell those six cases apart.

**Action:** Add an explicit plan decision. Either one short passage on `domain-context.md` that groups the six tickets by whether they update `docs/context/<project>/INDEX.md` (row and, for the audit count, the index file — no status names, no frontmatter keys, no steps), or a written out-of-scope line that the folder-level wording is the intended public description. Put a matching Definition of Done check on Task 1.1. Do not describe AC-16 as an update of the project index.

## WARNINGS

### W1: Hand pages can republish a closed optional-line list and drop `Audit`

AC-18 added optional `Audit` on the readiness block and did not edit the website. Question 18 names `Resume`, `Context`, and `Reason` only. Task 2.1's Definition of Done requires those three names. The plan's Additional Context says the skill also has `Audit` and that these pages must not paste its formula. A sentence that lists three optionals and stops is the same defect as "optional fifth `Reason`": the summary becomes the contract.

**Action:** The edited sentences should say the three names and that the skill is the norm for any further optional line, including `Audit`, without the formula. The Definition of Done should reject a closed list of three.

### W2: Task 2.1 shares two files with the shipped AC-17 copy

`website/docs/main-flow/workflow/standard-flow.md` and `website/docs/reference/agents/engineering-manager.md` already describe the As-Is Pack comment. Task 2.1 edits those files for the readiness sentence. The task text says to replace the retired wording. The Definition of Done does not require the AC-17 sentences to remain.

**Action:** Add a check that those two files still contain the As-Is Pack comment wording AC-17 shipped, and that `overview.md` is untouched.
