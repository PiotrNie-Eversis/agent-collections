New readers of `website/docs/` currently must learn the framework's internal taxonomy (SSOT, adapters, MCP) before finding the page relevant to their goal, and hit three genuinely divergent installation sequences depending on which page they land on (confirmed in code — see Gathered Information below). The business impact is entirely about first-time-reader comprehension and evaluator drop-off, as argued in the source report (`docs/specs/docs-ux-ui-analysis/`).

## Gap Analysis

All missing information and gaps found while grounding the BA-authored stories against the current codebase, together with provided answers where already resolved during the BA session, and one new question raised by this codebase pass.

### Question 1
#### DHI-648's acceptance criteria describe a AI-Hero-style "one clause per entry" template, but `agents/overview.md`, `skills/overview.md`, and `prompts/overview.md` already use structured multi-column reference tables (not the "bare names vs. paragraphs" inconsistency the source report assumed) — richer than AI Hero's single-line format. Should the plan (a) replace the existing tables with true one-liners (dropping columns like Packaging/Tools/Used By), (b) add a one-line plain-language summary above/alongside the existing tables without removing them, or (c) treat this as already close enough on `prompts/overview.md` (which is nearly one-liner already) and scope DHI-648 down to `agents/overview.md` and `skills/overview.md` only?

**Resolved 2026-09-04 — Option B.** A one-line plain-language summary is added above each entry (or above each phase-grouped block); the existing multi-column reference tables (Role/Packaging/Summary/Tools for Agents; Skill/Description/Used By for Skills; Prompt/Role/Description for Prompts) stay exactly as-is beneath it. Nothing is removed. Decision made against a real mockup built from the actual `docs/agents/overview.md` rows (Business Analyst, Context Engineer, Architect) — see `docs/specs/dhi-641/` conversation; mockup not persisted as a repo file, decision recorded here instead.

**Impact on DHI-648 scope/AC:**
- The story's current acceptance criteria (in `docs/specs/docs-ux-ui-analysis/jira-tasks.md` / DHI-648) say "every entry follows one consistent pattern: name — bolded title — one clause outcome," worded as a *replacement*. That needs a **Plan-stage AC amendment**: the one-liner is *added above*, tables are *preserved*, not replaced.
- Applies to all three pages (Agents, Skills, Prompts), not just two — Option C's descope idea (skip Prompts) was **not** chosen, so `prompts/overview.md` is in scope too, even though it's already fairly close to one-liner style; it still gets a summary line per entry for consistency across all three pages.
- Sizing: adding a line per entry across 3 pages (Agents: ~13 roles, Skills: ~40 skills, Prompts: ~28 prompts) without restructuring tables is additive, mechanical work — likely still **Medium (5-8)** as originally sized, not larger, since no table restructuring or content loss to reconcile.
- The existing sequencing dependency on `docs/specs/website-docs-skills-prompts-sync/` (content-accuracy audit) is unaffected by this decision — still applies before/alongside this story.
