**User story:** Jako architekt frameworka chcę mieć spisaną specyfikację mapowania adapterów, żeby każda reguła core wiedziała, jak przekształcić się do natywnego formatu każdego narzędzia.

## Wpływ biznesowy

Otwiera **Work Stream 2**: bez tej specyfikacji implementacje Cursor (DHI-524), Claude Code (DHI-526), OpenCode placeholder (DHI-525) i tooling sync (DHI-527) będą niespójne. Domknięcie „core SSOT → narzędzie” jest warunkiem instalera (5.x), izolacji kontekstu (3.x) oraz pilota EOG (frontend Cursor / backend Claude).

## Kryteria akceptacji (z Jira)

1. Spec mapowania jest kompletna: definiuje mapowanie pól dla **Cursor** (`globs`, `description`, `alwaysApply`), **Claude Code** (`scope`, `commands`) oraz **OpenCode** (manifest placeholder)
2. Po przejściu reguły core przez spec **struktura wyjścia jest jednoznaczna** dla implementujących Story 2.2–2.4
3. Spec stwierdza, **które artefakty core** emituje każdy adapter (tylko rules vs rules + prompts + skills summaries)
4. Dziedziczone AC SDD (folder spec, research → plan → implement → review → Fine)

### Pytanie 4
#### Jaki kształt wyjścia Claude Code ma być „jednoznaczny” dla DHI-526?
**Opcje:**  
**A)** Jeden `CLAUDE.md` (sekcje = domain/orchestration rules); skills/prompts poza adapterem (MCP / AGENTS)

**Odpowiedź (zatwierdzona 2026-08-05):** **A** — jeden `CLAUDE.md` z sekcjami; skills/prompts poza adapterem.

### Pytanie 5
#### Skąd adapter bierze `description` / `globs` / `alwaysApply` (core nie ma front matter)?
**Opcje:**  
**A)** Sidecar przy regule (np. `agent-core.cursor.yml`)  
**B)** Centralna mapa w warstwie adaptera (`adapters/cursor/rule-map.yaml`)  
**C)** Czysta konwencja ścieżki/folderu (orchestration→alwaysApply; frontend→globs zestaw; architecture roles→attach-only) + wyjątki w małej tabeli  

**Odpowiedź (zatwierdzona 2026-08-05):** **B** — centralna mapa w warstwie adaptera (np. `adapters/cursor/rule-map.yaml`); w DHI-523 opis kontraktu mapy w spec (bez tworzenia pliku YAML).

### Pytanie 6
#### Jak głęboki ma być placeholder OpenCode w tej story?
**Opcje:**  
**A)** Minimalny manifest (id adaptera, status `placeholder`, lista TBD outputs) wystarczający pod AC
