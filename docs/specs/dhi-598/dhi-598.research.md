## Business Impact

Cursor users start workflows by attaching prompt files with `@`. Because the Docusaurus site mirrors every prompt under `website/docs/prompts/`, the `@` picker shows **two** paths for the same stem (e.g. `eversis-plan`). That undermines trust in which file is authoritative.

Slash `/eversis-*` entries are a **single registered** Cursor-channel entrypoint. Combined with (optional, separate) ignore of `website/docs/prompts/`, users get a clear path: type `/`, pick one command, agent follows `.ai/prompts` SSOT.

Stable prompt ids remain vendor-neutral SSOT; slash packaging is Cursor-only emit (same philosophy as `.cursor/rules/*.mdc`).

### Content strategy for generated files

Prefer **thin shims**, not full prompt copies:

1. Title / stable id
2. Explicit path to SSOT: `.ai/prompts/{public\|internal}/eversis-<id>.md`
3. Short instruction: load and follow that file; ignore `website/docs/prompts/` copies
4. Optional: embed the “Executable prompt” section from SSOT if present (keeps `/` self-contained when `@` attach is awkward)

Marker: same generator family as rules (`GENERATED by adapters/cursor/generate.mjs`).

### Inventory / map design

Two viable approaches:

1. **Convention scan** — discover all `.ai/prompts/{public,internal}/eversis-*.md`; emit one command per file (no YAML).
2. **Explicit map** — `adapters/cursor/command-map.yaml` (or section in `rule-map.yaml`) listing id, source, output, optional `enabled` / `audience: public|internal`.

**Recommendation:** convention scan for v1 (deterministic, no drift vs prompt tree) **plus** optional deny-list in YAML for prompts that must not become slash commands (e.g. BA Docs if consumer policy excludes them). Public + internal both emitted (internal are EM-routed but still useful as `/eversis-research`, `/eversis-plan`).

### Sync / check

Extend Cursor generate so `npm run sync:adapters` regenerates commands; `sync:adapters:check` fails on drift for `.cursor/commands/eversis-*.md` the same way it does for rules. Orphan generated files (prompt deleted) should be removed or flagged — plan must specify cleanup policy (**recommended:** delete orphans that match `eversis-*.md` under `.cursor/commands/` and carry the GENERATED marker).

### Question 2
#### Emit public only, or public + internal?
**Answer (2026-08-07):** **BOTH** — public + internal (~28 commands). Deny-list only for explicit exclusions.

### Question 3
#### Thin path pointer only, or embed Executable prompt body?
**Answer (2026-08-07):** **HYBRID** — always emit pointer to `.ai/prompts/...`; embed the `## Executable prompt…` section when that heading exists; otherwise pointer-only fallback.

Slash commands in Cursor inject the **command file body** into the chat. That body is what the agent sees first — it does **not** automatically open the SSOT under `.ai/prompts/` unless the agent follows an instruction to read/attach it.

Nearly all framework prompts already have a marked section `## Executable prompt (attach in Cursor)` (the runnable instructions). Above that section sits docs/UX prose (Usage, What It Does, tables) meant for humans / Docusaurus.

| Variant | What `/eversis-*` contains | Pros | Cons |
|---------|----------------------------|------|------|
| **POINTER_ONLY** | Title + stable id + “read/follow `.ai/prompts/.../eversis-*.md`” (+ prefer `.ai` over `website/`) | Single SSOT; tiny generated files; never drifts from prompt edits beyond path | Agent may forget to open the file; `/` alone is weak without a follow-up `@` or read |
| **EMBED_EXECUTABLE** | Above pointer **plus** copy of the `## Executable prompt…` section from SSOT at generate time | `/` is self-contained — agent gets the workflow text immediately | Dual copy of executable text until next sync; docs prose still only in `.ai` |
| **HYBRID** (chosen) | Pointer always; embed Executable **when** that heading exists | Same as EMBED for most prompts; POINTER fallback if heading missing | Same sync-drift risk as EMBED for the embedded part |

**Not recommended:** pasting the **entire** `.ai/prompts` file into `.cursor/commands/` (frontmatter, Docusaurus admonitions, full docs) — that recreates a second full SSOT and worsens drift.

**Practical note:** With HYBRID, `sync:adapters` must re-run after prompt executable edits (already true for rules).
