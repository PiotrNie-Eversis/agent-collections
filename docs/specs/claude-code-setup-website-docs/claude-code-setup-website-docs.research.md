## 1. Cel i zakres

**Pytanie:** czy publiczna dokumentacja (`website/docs/**`) opisuje Claude Code zgodnie z tym, co framework faktycznie teraz robi po implementacji `claude-code-setup.plan.md` (fazy A–H), czy nadal odzwierciedla stary, niepełny stan (ten, który `claude-code-setup.research.md` opisało jako F1–F11)?

**W zakresie:** wyłącznie pliki `website/docs/**` wymienione w §3 (znalezione przez `grep -rl` po `claude`/`CLAUDE.md`/`.claude/`). Klasyfikacja każdego nieaktualnego stwierdzenia + rekomendacja korekty.

**Poza zakresem:** treść merytoryczna niedotycząca Claude Code (np. sekcje o Cursorze, OpenCode, WNF-03 poza tabelą multi-agent), zmiany w `docs/architecture/**` i `adapters/claude/README.md` (już poprawione w ramach `claude-code-setup.plan.md`, fazy C/E/G), publikacja/hosting strony (`website/` buduje się lokalnie, brak produkcyjnego URL — bez zmian).

**Metoda:** `grep -rl -i "claude"` po `website/docs/`, pełny odczyt 8 trafionych plików, porównanie każdego stwierdzenia o Claude Code z rzeczywistym zachowaniem po fazach A–H (zweryfikowanym testami w `claude-code-setup.plan.md`).

## 2. Stan wyjściowy — co zmienił `claude-code-setup.plan.md`

Skrót (pełny opis: `claude-code-setup.research.md` F1–F11 + `claude-code-setup.plan.md` fazy A–H, wszystkie zaimplementowane i zweryfikowane w tej samej sesji):

| Obszar | Przed (opisywane w F1–F11) | Po (zaimplementowane) |
|---|---|---|
| MCP | Instalator pisał tylko `.cursor/mcp.json`; `--agents=claude` dawał **zero** serwerów MCP dla Claude | `.mcp.json` w roocie konsumenta, składnia natywna Claude (`${VAR}`, `${CLAUDE_PROJECT_DIR:-.}`), jawny `env.AGENT_COLLECTIONS_HOME` |
| Slash commands | Brak — tylko instrukcje tekstowe w `CLAUDE.md` | `.claude/commands/eversis-*.md` — ten sam mechanizm co `.cursor/commands/` (DHI-598), `/eversis-implement` działa tak samo w obu narzędziach |
| Skille | Wyłącznie przez MCP lub ręczny odczyt `.ai/skills/*/SKILL.md` | **Natywnie** przez `.claude/skills/eversis-*/` (symlink/copy z instalatora) — Claude Code odkrywa je bez MCP; `user-invocable: false` chroni przed zaśmieceniem menu `/` |
| Ustawienia / izolacja | Brak `.claude/settings.json`; `.claudeignore` był no-opem dla Claude Code | `.claude/settings.json` z `permissions.deny` generowanym z klas `.claudeignore` — realny, egzekwowany mechanizm |
| Kontrakt AGENTS.md | Dokumentacja kazała edytować `AGENTS.md`, którego Claude Code nie czyta automatycznie | `.claude/CLAUDE.md` — nowa, seedowana raz powierzchnia własna konsumenta; `AGENTS.md` importowany przez `@AGENTS.md` gdy istnieje |
| Reguły z globami | Wszystkie reguły w jednym `CLAUDE.md` (349 linii), w tym `eversis-accessibility` ładowana w każdej sesji | `.claude/rules/eversis-accessibility.md` z `paths:` — ładowana tylko dla plików UI; `CLAUDE.md` spadł do 334 linii |

**Wniosek:** capability-parity między Cursorem a Claude Code jest teraz w praktyce **wyższy niż opisuje dziś strona www** — w jednym miejscu (skille) Claude Code ma nawet **pełniejszy** mechanizm niż Cursor (natywny mirror `.claude/skills/` vs. Cursor, który świadomo nie ma mirrora `.cursor/skills` i zostaje przy MCP).

## 3. Znalezione pliki i nieaktualne stwierdzenia

8 plików zawiera odniesienia do Claude Code (`grep -rl -i claude website/docs/`). Poniżej — plik po pliku, z numeracją **W1–W9** (Website), żeby nie kolidować z F1–F11 z poprzedniego research.

### `website/docs/isolation.md`

**W1 — tabela "Multi-agent MVP" (linia 52), Średnia**

```
| Claude Code | `CLAUDE.md` | MCP / read `.ai/skills` |
```

Nieaktualne w kolumnie "Packaging" (brak `.claude/commands/`, `.claude/rules/`) i "Skills" (brak natywnego `.claude/skills/`). Ta sama tabela dla Cursora jest poprawna i się nie zmienia.

### `website/docs/framework-reference.md`

**W2 — linia 65, Niska**

> "Load prompts by stable id under `.ai/prompts/`. Optional Cursor `@` attach when surfaced, or `/eversis-*` when `.cursor/commands/` was generated by the Cursor adapter."

Sugeruje, że `/eversis-*` istnieje tylko po stronie Cursora. Dziś identyczny mechanizm istnieje dla `.claude/commands/`.

**W3 — linia 76, Wysoka**

> "**Claude Code** — root `CLAUDE.md`; skills via MCP / `AGENTS.md`."

Dwa błędy naraz: (a) brak wzmianki o `.claude/commands/` i `.claude/rules/`; (b) `AGENTS.md` jako miejsce ładowania skilli/instrukcji dla Claude Code — to dokładnie F7 z poprzedniego research (Claude Code nie czyta `AGENTS.md` automatycznie). Powinno wskazywać `.claude/CLAUDE.md` (+ opcjonalny import `@AGENTS.md`).

### `website/docs/intro.md`

**W4 — linia 41, Niska**

> "Cursor may generate thin `/eversis-*` shims under `.cursor/commands/` via the adapter (DHI-598)."

Jak W2 — jednostronne, pomija Claude Code.

### `website/docs/getting-started/mcp-setup.md`

**W5 — linie 74–76, "Claude Code note", Krytyczna**

> "Claude MVP uses **`CLAUDE.md`** plus skills via MCP / reading `.ai/skills` — not a full Cursor MCP parity matrix. Prefer documenting which MCP servers your team enables in the consumer stack rule."

To jest werbatim opis **problemu, który `claude-code-setup.plan.md` Faza A zamknęła** (F3/F4/F9 — instalator nigdy nie konfigurował MCP dla Claude). Zdanie jest teraz nieprawdziwe: Claude Code dostaje działający `.mcp.json` tym samym mechanizmem co Cursor. To najpoważniejsza rozbieżność w całym audycie — strona wprost odradza czytelnikowi oczekiwanie funkcji, która już działa.

**W6 — linia 27, Średnia**

> "Point MCP at the built entry (installer merges this into `.cursor/mcp.json`)"

Prawdziwe dla Cursora, ale niepełne — ten sam JSON (po transformacji składni) merguje się też do `.mcp.json` dla Claude Code od Fazy A.

### `website/docs/getting-started/prerequisites.md`

**W7 — linia 15, Wysoka**

```
| **Claude Code** | Shipped adapter: root `CLAUDE.md` from core rules; skills via MCP / `AGENTS.md` |
```

Ten sam wzorzec błędu co W3 (AGENTS.md + brak commands/rules/native skills).

### `website/docs/getting-started/installation.md`

**W8 — linia 89, sekcja "Customising stack (Cursor vs Claude)", Wysoka**

```
| Claude Code | `AGENTS.md` (do not hand-edit generated `CLAUDE.md`) |
```

F7 ponownie — powinno być `.claude/CLAUDE.md`.

**W8a — linie 91–95, sekcja "4. Skills and prompts (MVP)", Wysoka**

> "This MVP does not ship a full mirror under `.cursor/skills` or `.cursor/prompts`. The Cursor adapter **does** generate thin slash shims under `.cursor/commands/` from `.ai/prompts`..."

Cała sekcja mówi wyłącznie o Cursorze. Brakuje: (a) `.claude/commands/` — ten sam mechanizm co Cursor; (b) `.claude/skills/` — **Claude Code ma pełny natywny mirror skilli, czego Cursor świadomie nie ma** (asymetria warta jednego zdania, bo dziś czytelnik wywnioskowałby odwrotnie). Brak też wzmianki o `.claude/settings.json` / `.mcp.json` w tym samym kroku instalacji.

### `website/docs/getting-started/migration-from-cursor-collections.md`

**W9 — linia 42–43, Wysoka** — "Cursor stack in `eversis-project-stack.mdc`, Claude stack in `AGENTS.md`" → F7, jak W3/W7/W8.

**W9a — tabela "Generated (adapters)" linia 51, Średnia** — brakuje `.claude/commands/eversis-*.md`, `.claude/rules/*.md` obok `.cursor/rules/eversis-*.mdc` / `CLAUDE.md`.

**W9b — tabela "Capability matrix (Cursor vs Claude MVP)" linie 57–65, Krytyczna** — najgęstsze skupisko nieaktualnych twierdzeń w całym audycie:
- `Skills`: "Same MCP / read `.ai/skills`; instructional load via `AGENTS.md`" — nieprawda po Fazie D (natywny `.claude/skills/`) i F7 (nie `AGENTS.md`).
- `Slash commands`: "Prefer `/eversis-*` after sync; Claude Code uses prompt ids / `CLAUDE.md`" — nieprawda po Fazie C: Claude Code ma **te same** natywne `/eversis-*` co Cursor, nie tylko "prompt ids".
- Brak wiersza dla ustawień/`permissions` (`.claude/settings.json` nie ma dziś odpowiednika w tej tabeli, mimo że `.cursorignore`/`.claudeignore` już tam jest).

### `website/docs/getting-started/quick-wins.md`

**W10 — linia 9, Niska** — "this MVP does not ship a full `.cursor/skills` mirror" jest nadal prawdziwe dla Cursora (bez zmian), ale w kontekście całego audytu warto rozważyć jedno zdanie kontrastujące z Claude Code, żeby czytelnik nie uogólniał tego na cały framework. Nie jest to błąd, tylko okazja do doprecyzowania — najniższy priorytet w tym dokumencie.

## 4. Wzorzec błędu — jedna przyczyna źródłowa

Wszystkie W1–W9 sprowadzają się do **trzech** powtarzających się, mechanicznych błędów, które prawdopodobnie da się poprawić bez przepisywania prozy:

1. **"AGENTS.md" jako miejsce customizacji Claude Code** (W3, W7, W8, W9) — wszędzie zamienić na `.claude/CLAUDE.md` (dokładnie F7 z oryginalnego research, powielone w 4 miejscach na stronie www).
2. **Brak `.claude/commands/`** przy każdej wzmiance o `.cursor/commands/` (W2, W4, W8a, W9a, W9b) — symetryczne dopisanie.
3. **Skille opisane jako "MCP-only" dla Claude Code** (W1, W3, W7, W8a, W9b) — dopisanie natywnego `.claude/skills/`, z zaznaczeniem że to **przewaga** nad Cursorem, nie parytet.

Dodatkowo **W5** (mcp-setup.md) to osobny, najpoważniejszy przypadek — nie brakujące zdanie, tylko zdanie **czynnie wprowadzające w błąd** (mówi wprost "not a full... parity matrix" o czymś, co teraz jest pełną parytetową ścieżką).
