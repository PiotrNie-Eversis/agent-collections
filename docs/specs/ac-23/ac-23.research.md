### Codebase

Docusaurus 3 (`website/package.json` site; live HTML generator meta: `Docusaurus v3.10.2`) takes the site origin from the `url` field in `website/docusaurus.config.ts`. That field is a string literal:

```ts
url: 'http://localhost:3000',
baseUrl: '/',
```

`baseUrl` is `/`, which matches how the site is served. There is no environment variable, Vercel env rewrite, or second config that overrides `url` at build time. Root `vercel.json` only sets install, build, and output directory. The production HTML is the static build (response headers on 2026-09-23: `server: Vercel`, `x-vercel-cache: HIT`, `last-modified: Sat, 12 Sep 2026 14:50:43 GMT`).

Docusaurus writes `url` into absolute metadata at build time. Live checks on 2026-09-23:

| Surface | Observed value |
|---|---|
| `https://agent-collections.vercel.app/` `<link rel="canonical">` | `http://localhost:3000/` |
| same page `og:url` | `http://localhost:3000/` |
| same page `og:image` and `twitter:image` | `http://localhost:3000/img/opengraph.png` |
| `hreflang` alternates | `http://localhost:3000/` |
| `https://agent-collections.vercel.app/docs/getting-started/start-here/` canonical and `og:url` | `http://localhost:3000/docs/getting-started/start-here` |
| `https://agent-collections.vercel.app/sitemap.xml` `<loc>` entries | `http://localhost:3000/...` |

`themeConfig.metadata` in the same config only adds `og:type`, image dimensions, and alt text. It does not set `og:url` or the canonical link. Those come from `url`.

Other `localhost:3000` strings in the repo are example dev-server URLs in prompt and accessibility-skill docs (`eversis-implement-ui`, `eversis-accessibility-auditing`). They are not the site config and do not affect production HTML.

The homepage HTML also contains Docusaurus's standard base-URL mismatch banner script. `baseUrl` is `/`, and the live path is `/`, so that script is the usual guard, not the metadata defect.

## Gap Analysis

The cause is verified. The questions below are the ones that were open from the task text; each has an answer from the live site, the config, or the user's stated origin.

### Question 1

#### Why does production metadata show `http://localhost:3000` when the site is served at `https://agent-collections.vercel.app/`?

`website/docusaurus.config.ts` sets `url` to `http://localhost:3000` and comments that this is a local placeholder because public hosting was deferred. The site is now deployed. Vercel serves the static build produced with that `url`, so canonical, `og:url`, `og:image`, `twitter:image`, hreflang, and `sitemap.xml` all use localhost. This is not a cache-only or runtime header bug: the tags are in the HTML body of the build (`last-modified` 2026-09-12).

### Question 2

#### Is a Vercel environment variable or rewrite supposed to replace that origin and failing?

No. Nothing in `vercel.json` or the Docusaurus config reads an environment variable for `url`. The localhost value is the value that was compiled in.

### Question 3

#### What origin should metadata use?

The task states `https://agent-collections.vercel.app/`. Docusaurus's `url` field is the site origin without a trailing slash (`https://agent-collections.vercel.app`). `baseUrl` stays `/`.

### Question 4

#### Do the other `localhost:3000` mentions in the repo cause this?

No. They are examples of a local app dev server in UI-verification and accessibility docs. Production metadata comes only from `website/docusaurus.config.ts` `url`.
