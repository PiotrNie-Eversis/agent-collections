## Wildly Important Goal

**Goal**: Make Start here a scannable role-aware onboarding map so QA/BA/PO can choose a path and reach Prerequisites/Installation without Prerequisites prose or shell/MCP jargon on the critical path.

**Success Measure**: `start-here.mdx` ships with Tabs for the three roles, short Prerequisites pointer, plain success criteria and next steps, no competing unlabeled checklists / In this section wall, all listed internal links are site-absolute `/docs/…`, and `npm run website:build` passes.

**Do NOT touch / do NOT add**:

- Full rewrite of Prerequisites, Installation, or MCP setup pages (link targets only)
- Installer / MCP runtime / Docker image changes
- Polish localization of the docs site
- New npm dependencies
- Role **table** as the primary chooser (Tabs only — research Q2)

## Proposed Solution

Convert `website/docs/getting-started/start-here.md` to **`start-here.mdx`** and rebuild the page as:

1. Short intro + tip (map, not encyclopedia) — keep Delivery Standard one-liner.
2. **Tabs** (`groupId="start-here-role"`) with three `TabItem`s: QA/BA/PO (Cursor-first), developer/QA tech, maintainer/MCP — each path links **Prerequisites before or together with** Installation; maintainer tab points to MCP/Node depth without forcing QA through that list.
3. Shared (or per-tab) **short Prerequisites pointer**: ≤2 sentences naming AI editor (Cursor and/or Claude Code), Docker Desktop, and Git, plus link to Prerequisites — **no** Node/VS Code/accounts essay.
4. Plain-language **You’re done when…** and **Next steps** (Quick wins, Main Flow / workflow overview) — no shell flags, `export`, submodule/copy modes, or MCP skill internals as required reading.
5. Remove **In this section**; demote Requirements traceability and GitLab README/AGENTS off the primary path (optional short “Maintainers / canonical refs” note).
6. Keep/harden **site-absolute** `/docs/…` links; after rewrite, verify targets for Prerequisites, Installation, MCP setup, Quick wins, Domain Context, Framework (AC-61). Prefer local docs preview with a trailing-slash Start here URL when available; at minimum inspect link strings in the MDX and pass `website:build`.

```text
Start here (mdx)
├── Intro + tip
├── Tabs: QA/BA/PO | Developer/QA tech | Maintainer/MCP
│     └── short steps → Prerequisites (+ Installation) → …
├── Success criteria (plain language)
├── Next steps (Quick wins, Main Flow)
└── Optional demoted maintainers/canonical note
```
