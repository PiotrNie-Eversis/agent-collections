**User story:** As a team lead, I want coding, architecture, and quality rules organized by domain in the core so that frontend and backend teams receive guidance relevant to their area without cross-noise.

## Business Impact

Enables domain-scoped install profiles and monorepo isolation (later DHI-530/536) without forcing every agent to load full-stack noise. Completes Wave A rule extraction after orchestration (DHI-518).

## Acceptance Criteria (from Jira)

1. `frontend`, `backend`, `devops`, `architecture`, and `shared-types` each contain at least rules derived from legacy equivalents
2. Domain rules contain **no** references to a specific IDE, CLI, or vendor UI
3. Overlapping guidance is consolidated; domain scoping preserved
4. Inherited SDD AC
