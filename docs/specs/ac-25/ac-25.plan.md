## Wildly Important Goal

**Goal**: A consumer session can pass a project-relative `.docx` path to the docx tools and have that file opened from the consumer project mount.

**Success Measure**: A unit test opens a relative `docx_path` from a workspace root that is not `process.cwd()`, for load, validate, and backup, and the public MCP page plus both BA Docs skills state that contract.

**Do NOT touch / do NOT add**:

- No new bind mount, ingest tool, or support for files outside the consumer project (`~/Downloads`, host `/Users/...` paths).
- No change to `Dockerfile` `WORKDIR /app` or to the existing `/repo` and `/workspace` volumes.
- No change to domain-context tool behavior.
- No new package dependencies.

## Proposed Solution

Relative docx paths resolve against the same consumer workspace root that domain-context tools already use (`resolveWorkspaceRoot()`). Absolute paths stay as given, so a container path such as `/workspace/...` still opens, a host path such as `/Users/...` still fails with `Not a file` showing that path, and existing unit tests that pass an absolute temp path keep working.

One helper owns the rule. `loadDocx`, `validateDocxFile`, `backup_docx`, and an explicit `output_md_path` all use it. When `output_md_path` is omitted, the summary file stays beside the resolved `.docx`, which is already how `generate_summary_map` behaves once `loadDocx` returns a workspace absolute path.

A relative path that would leave the workspace root (for example `../`) is rejected. That keeps anchoring paths at `/workspace` from becoming a read of the rest of the container.

```text
docx_path
  absolute? → use it unchanged (path.resolve)
  relative? → join to resolveWorkspaceRoot()
              reject if the result is outside that root

container today
  /app          image WORKDIR (not a volume)
  /workspace    consumer project  ← relative docx paths land here
  /repo         framework checkout
```

Allowed seam (no implementation body):

```ts
export function resolveDocxPath(docxPath: string, workspaceRoot: string): string
```

`loadDocx`, `validateDocxFile`, and the backup helper take an optional workspace root and default it to `resolveWorkspaceRoot()` so production call sites stay one-argument and tests can pass a temp root that is not the process cwd.

- Error text continues to report the path that was opened. Do not include file contents in the `Not a file` error.
- No new network calls, credentials, or package dependencies.
