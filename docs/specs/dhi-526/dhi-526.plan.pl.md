## Wildly Important Goal

**Goal**: Dostarczyć działający adapter Claude Code, który z SSOT `.ai/` generuje jeden rootowy `CLAUDE.md` (H2 per zmapowaną regułę, pełny inline), tak by sesje Claude Code miały te same standardy co Cursor — bez plików Cursor-specific.

**Success Measure**: `node adapters/claude/generate.mjs` tworzy / odświeża committed `CLAUDE.md` z 7 sekcjami zgodnymi z Cursor `rule-map` + sekcją How-to; maturity Claude w mapping/README oznaczone jako generator shipped; review bez blockerów względem AC (z jawnym DEFER AC monorepo → DHI-528–530).

**Do NOT touch / do NOT add**:

- `.claude/rules/`, natywne Claude skills/commands/hooks (Q1=A)
- Kondensacja / `@import` treści reguł zamiast pełnego inline (Q2=A)
- Wspólna mapa `adapters/shared/` (Q3=A — osobna mapa Claude)
- Profile `--profile backend` / subset reguł (Q4=A — parity 7 id)
- `.claudeignore`, `claudeMdExcludes`, pełna izolacja monorepo (Q5=A → DHI-528–530)
- Sync CLI (DHI-527), OpenCode (DHI-525), MCP resolve (DHI-535), AGENTS epic (DHI-531/532)
- Zmiana generatora Cursor / treść merytoryczna `.ai/rules/*.md`
- Nadpisywanie consumer `eversis-project-stack` / BA Docs symlinki


**Kształt `CLAUDE.md` (kontrakt DHI-523 §5 + Q1/Q2=A):**

```text

- Scope instrukcyjny: preferuj ścieżki backend / nie ładuj artefaktów Cursor (AC #2 + Q5=A)

…pełne body z .ai/rules/orchestration/agent-core.md…

## eversis-testing-and-terminal
…

(…kolejne 5 id jak w Cursor rule-map…)
```

**Przepływ generatora (pseudo):**

```text
findRepoRoot → parse rule-map.yaml (version: 1, rules[{id,source}])
  → validate id/source (repo-relative, source exists)
  → build document: header + How-to (stały szablon) + for each rule: ## id + body
  → write root CLAUDE.md (lub --out/<root>/CLAUDE.md)
  → re-run nadpisuje bez ręcznej edycji
```

```text
.ai/rules/*.md ──► adapters/claude/rule-map.yaml ──► generate.mjs ──► CLAUDE.md
                         ▲
                         └── te same id/source co adapters/cursor/rule-map.yaml
```

## Kontekst techniczny

Konwencje projektu dla implementera — **czytać tę sekcję zamiast ponownego odkrywania**.

### Instrukcje projektu

- `AGENTS.md` — core SSOT w `.ai/`; Delivery Standard SDD
- `.cursor/rules/eversis-agent-core.mdc` / `.ai/rules/orchestration/agent-core.md` — bramki research/plan; draft do approve
- `.cursor/rules/eversis-project-stack.mdc` — to repo = framework/docs; **nie** ładować skills backend/frontend product
- Mapping: `docs/architecture/adapter-mapping.md` — emit matrix; Claude = rules → `CLAUDE.md`; skills/prompts **nie** emit

### Architektura i wzorce

- Adapter **nie** jest właścicielem treści — tylko opakowanie
- Metadane opakowania w warstwie adaptera (`rule-map.yaml`), **nie** w `.ai/rules/*.md`
- Cursor: wiele plików `.mdc`; Claude (MVP): **jeden** plik `CLAUDE.md`
- Nazewnictwo id: `eversis-<stable-id>` jak w Cursor
- Marker: `<!-- GENERATED by adapters/claude/generate.mjs — do not edit; re-run the generator -->`
- Opcjonalnie `--out <dir>`: zapisz `CLAUDE.md` pod wskazanym rootem (jak Cursor `--out`)

### Tech Stack

- Node.js **18+** (ESM `import`, `node:fs` / `node:path` / `node:url`)
- **Zero** zależności npm w generatorze (jak Cursor)
- Brak test runnera w tym repo dla adapterów — weryfikacja = komendy shell + `rg` / `test -f`
- Pakiet manager: n/a dla tej story

### Styl kodu i standardy

- Wzoruj się na `adapters/cursor/generate.mjs`: `fail()`, `findRepoRoot`, walidacja ścieżek repo-relative, brak `..` escape
- Parser YAML: constrained (wystarczy `version` + `rules[]` z polami skalarnymi `id`/`source`) — **bez** `globs`/`alwaysApply`/`description` w mapie Claude
- Komunikaty błędów na stderr; exit ≠ 0 przy fail
- How-to: tool-agnostic; **zakaz** wymagań `.cursor/commands` jako jedynego entry
