## Technical Context

### Architecture & Patterns

**`spec-driven-development.md` (canonical) must include:**

1. Lifecycle: Ideate → Research → Plan → Implement → Review → Fine (vendor-neutral)
2. Human gates (research before plan; plan before code; Fine draft; no auto Jira post)
3. Spec folder `docs/specs/<issue-kebab>/`; required `*.research.md`, `*.plan.md` when Full/SDD applies
4. Delivery Standard block (copy-ready) with stable prompt ids + optional Cursor attach note
5. Note: this framework repo gitignores `docs/specs/dhi-*/`; consumers choose commit vs ignore for their specs
6. Pointer to EM readiness + orchestration skill for adequacy checklist (do not duplicate the full checklist)

**`agent-core.md`:**

- Update plain-language Lifecycle so Research/Plan are visible (or Ideate explicitly includes them)
- Short pointer to `spec-driven-development.md` as mandatory Delivery Standard
- Keep existing orchestration steps / hard limits

**Delivery Standard template text (Q4 A):**

```text
## Delivery Standard

This story follows full spec-driven development (mandatory under Agent Collections / epic DHI-515 when applicable).

* Spec folder: docs/specs/<issue-kebab>/
* Research: <issue-kebab>.research.md — required before plan
* Plan: <issue-kebab>.plan.md — required before implementation
* Implement: load eversis-implement (approved plan attached)
* Review: load eversis-review before Done
* Fine: QA comment draft per eversis-fine-handoff

Do not start implementation without approved research and plan artifacts.

Optional (Cursor): you may also attach the same prompts with @eversis-implement / @eversis-review if your project surfaces those files in Cursor.
```
