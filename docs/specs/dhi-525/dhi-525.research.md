**User story:** As a framework maintainer, I want an OpenCode adapter placeholder so that future integration does not require rewriting the core.

## Business Impact

Closes the third Work Stream 2 slot (Cursor / Claude / OpenCode): the install wizard (5.6) and docs can advertise OpenCode as **`placeholder`**, not invent a contract ad hoc. Protects the **core SSOT** invariant — OpenCode format changes stay in the adapter layer. Does not unblock the EOG pilot (Cursor+Claude), but reduces drift risk and matches assumption #3 (OpenCode stub only).

## Acceptance Criteria (from Jira)

1. **Manifest:** GIVEN the adapter architecture WHEN OpenCode support is stubbed THEN a manifest/config template exists documenting expected fields and core mapping hooks
2. **Core stability:** GIVEN the placeholder WHEN reviewed THEN it is clear the core remains unchanged when the OpenCode format evolves
3. **Index isolation:** GIVEN repository structure WHEN inspected THEN OpenCode adapter files are excluded from other agents’ indexes (see Story 3.2 / [DHI-529](https://eversis.atlassian.net/browse/DHI-529))
4. Inherited SDD AC (spec folder, research → plan → implement → review → Fine)
