## Wildly Important Goal

**Goal**: Zmaterializować placeholder adaptera OpenCode (struktura + interfejs), który mapuje core `.ai/rules` przez `instructions`, bez zmiany treści core i bez pełnego generatora.

**Success Measure**: Istnieją identyczne `adapters/opencode/opencode.jsonc` i root `opencode.jsonc` z `$schema` + globs §6.1 oraz komentarzem PLACEHOLDER; README niesie maturity `placeholder` i inwariant „core unchanged”; `.cursorignore` wyklucza ścieżki OpenCode-only; CHANGELOG / `.ai/README` / mapping §6 wskazują materializację; review bez BLOCKER vs AC Jira (przy Q3=B: pełna triada ignore = follow-up DHI-529).

**Do NOT touch / do NOT add**:

- Generator / skrypt sync (Q2=A) — żadnego `generate.mjs` dla OpenCode
- Treść `.ai/rules/**` (inwariant AC #2)
- Root `AGENTS.md` (Q6=A)
- Pełna triada `.claudeignore` / `.opencodeignore` ani strategia izolacji (DHI-528–529) — poza minimalnym `.cursorignore`
- Adapter Claude (526), sync CLI (527), MCP (535), installer / wizard
- Agent profiles / permissions / proprietary keys poza `$schema` + `instructions`
- Nowe zależności npm / `package.json`
- Commit `docs/specs/dhi-*` (local-only)

## Technical Context

### Project Instructions

- Core SSOT = `.ai/`; adapter tylko konsumuje / wskazuje (`.ai/README.md`, AGENTS.md)
- Mapping: `docs/architecture/adapter-mapping.md` §6 (placeholder OpenCode)
- Emit matrix: OpenCode = `placeholder`; wizard nie może obiecywać pełnego adaptera
- Local-only: `docs/specs/dhi-*/` gitignored
- Hard limits implement: nie wychodzić poza plan; nie dodawać zależności bez zgody

### Architecture & Patterns

| Artefakt | Rola |
|----------|------|
| `adapters/opencode/opencode.jsonc` | Kanoniczny stub config (JSONC) |
| Root `opencode.jsonc` | Demonstracja w framework repo (identyczna treść) |
| `adapters/opencode/README.md` | Maturity, status block §6.3, dual surface, sync rule, checklista ignore → 529 |
| `.cursorignore` | Minimalne wykluczenie ścieżek OpenCode z indeksu Cursor |
| Docs (Q7) | Discoverability + sync mapping §6 |

**Status block (wymagany w README):**

```text
adapter: opencode
maturity: placeholder
emits: opencode.jsonc (instructions → .ai/rules globs); optional AGENTS.md pointer (existing root; unchanged)
does_not_emit: full skill/prompt mirrors, ignore triad, production-grade agent profiles
```

**Inwariant AC #2 (README, obowiązkowo):** zmiany formatu OpenCode = edycja warstwy `adapters/opencode/` (+ sync root); **nigdy** przepisywanie `.ai/rules` pod OpenCode.

**Uwaga Q5=A:** globs `*.md` ładują też `README.md` domen — zaakceptowane; README adaptera może wspomnieć „refine when shipped”.

### Tech Stack

- Brak runtime / generatora (Q2=A)
- JSONC ręcznie utrzymywany; `$schema`: `https://opencode.ai/config.json`
- Weryfikacja: `test` / `rg` / opcjonalnie `node -e` do parse JSON po usunięciu komentarzy **tylko jeśli potrzebne** — preferuj `rg` + istnienie plików
- Brak `package.json` / npm

### Code Style & Standards

- Komentarze JSONC: angielski, zwięzłe (PLACEHOLDER + core SSOT)
- README adaptera: angielski lub PL+EN jak sibling `adapters/cursor/README.md` (prefer **angielski** jak Cursor README dla spójności frameworka)
- Nie inventować proprietary keys w config
- Nie edytować `AGENTS.md`
