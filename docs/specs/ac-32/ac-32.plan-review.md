## WARNINGS

### W1: Soft convention — success depends on agent compliance, not a failing check

Evidence: Proposed Solution and Stop Rules correctly forbid a folder-creation / word-count script. Phase Verification and DoD are `rg` string checks plus `sync:*:check`. QA checklist items for “uses topic folder / asks on collision / does not create exact key” cannot be proven in CI.

Action: Keep as accepted product risk; Code Reviewer should treat conflicting inspect one-liners as BLOCKER-level review findings even when `rg ac-20` passes.

### W2: Bare `<issue-kebab>` / `<issue>` placeholders can still steer new folders to exact key only

Evidence: Plan Task 1.1 clue allows `<issue-kebab>` beside the new example. Codebase still has operative inspect paths: skill L80 `docs/specs/<issue>/`, `eversis-implement.md` L69, `engineering-manager.md` L31, `eversis-research.md` L48/L68. Agents that substitute only the Jira key into those placeholders recreate today’s exact-key folders for zero-hit creates, fighting Success Measure step 5.

Action: In Phase 1–2 edits, either redefine the placeholder as `key-topic-slug` in the same sentence as the example, or replace the inspect one-liner so it cannot be read as “open `docs/specs/ac-32/` only.”

### W3: Always-applied / orientation surfaces outside Files still teach the old shape

Evidence: `.cursor/rules/eversis-project-stack.mdc` L38 (`alwaysApply: true`) still says `docs/specs/<issue-kebab>/`. Same placeholder in `AGENTS.md`, root `README.md`, scaffolding, website `standard-flow.md` / `quick-wins.md`. Plan Improvements lists most of these; **project-stack is not named** there. Research scoped them as non-`task-522` surfaces — intentional narrow scope, but they remain high-visibility in Cursor sessions.

Action: Do not expand AC-32 without approval; implementer should not “fix” them ad hoc. Consider a one-line Improvement note for `eversis-project-stack` so Fine/follow-up does not forget the alwaysApply vector. Not a blocker for this approved scope.

### W4: Cross-file algorithm drift is the highest execution risk named in the plan itself

Evidence: Phase 5 Clues call out “read that still creates `docs/specs/ac-2/` beside a topic folder” and “boundary that takes `ac-20` as AC-2.” Task 2.1 touches four SSOT files; Task 4.2 a fifth (hand-written website skill). DoD for Implement / engineering-manager only requires that they “odsyłają” to the read — a weak check if the old inspect sentence remains.

Action: Treat the orchestration skill as the only full five-step algorithm; other files must not keep a standalone `inspect docs/specs/<issue>/` that contradicts it. Prefer identical boundary wording (`ac-20` counterexample) where a short restatement is needed.

### W5: Zero-hit topic invention is underspecified

Evidence: Step 5 creates `docs/specs/<key>-<topic>/` with max three topic words, but no task says whether the agent derives words from the Jira title, asks the human, or stops when the title exceeds three words. Out-of-scope correctly forbids a word-count script.

Action: Optional one-sentence Stop Rule or Clue in Task 2.1 / research prompt: if a ≤3-word topic cannot be derived confidently, ask once before creating the folder. Not required to reopen Open Questions.
