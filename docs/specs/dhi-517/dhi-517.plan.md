## Proposed Solution

Create the `.ai/` tree as empty-but-documented stubs plus one sample file, matching the approved research structure. Root `.ai/README.md` is the AC #3 deliverable (mapping contract). Domain and skills/prompts READMEs state purpose and which follow-up story fills them. Sample rule proves neutral Markdown format without YAML front matter.

```text
agent-collections/
  .ai/
    README.md
    rules/{frontend,backend,shared-types,devops,architecture,orchestration}/
      README.md (+ orchestration/sample-lifecycle.md)
    skills/README.md
    prompts/{README.md, public/, internal/}
```

- Core rules = plain `.md` under `.ai/rules/<domain>/`
- Skills stay flat packages later (`eversis-*`); this story only reserves `.ai/skills/`
- Prompts preserve `public/` vs `internal/`
- Folder name `orchestration/` = Jira “shared orchestration”
- Adapters (later) generate Cursor `.mdc` / Claude packaging from core

### Tech Stack

- Deliverable: Markdown + directories in git
- Shell for mkdir / existence checks
- No app runtime, no new package dependencies

- Neutral wording in sample (no required `@eversis-*` / Claude front matter)
- Sample must include a clear banner: sample only; full extraction = DHI-518
- README mapping table aligned with research “Mapping contract”

### Testing Patterns

- No unit/e2e suite
- Deterministic inspect commands (see phase Verification)

- N/A
