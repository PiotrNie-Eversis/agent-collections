## Classification Taxonomy (for implement)

| Tag | Meaning | Typical examples |
|-----|---------|------------------|
| **Core** | Vendor-neutral knowledge/procedure; belongs in `.ai/` after neutralization | Orchestration lifecycle, skill bodies, Ideate/Implement prompts (content), BA/transcript skills |
| **Cursor-specific** | Depends on Cursor surfaces (`.mdc` front matter, `@` attach, slash commands, `.cursor/mcp.json` shape) | Command stubs, `.mdc` packaging, Cursor adapter inputs — keep in adapter layer or Cursor channel |
| **Deprecated** | Explicitly unused / superseded / do-not-port | None identified yet — must be proven, not assumed |

**Classification rules:**

1. Prefer **Core** for skill/prompt *content* even if today invoked via Cursor; packaging becomes Cursor-specific.
2. Mark **Cursor-specific** when the file’s only job is Cursor UX (commands, mdc wrappers) with no unique procedure beyond pointing at a prompt.
3. `eversis-project-stack.mdc` is **consumer-owned template** — Core as *template pattern*, not as framework SSOT content.
4. Domain skills (filters, frontend, backend, k8s, …) are **Core** (optional load via stack policy); not Deprecated.
5. BA Docs Word playbook skills remain **Core** but may be “optional module” in install profiles (not Deprecated).
