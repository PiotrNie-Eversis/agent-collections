### Path policy (hard)

Committed artifacts (research, plans, `docs/context/`, website docs) **must not** contain machine-local absolute paths (e.g. `/Users/<name>/…`, `/home/<name>/…`). Use:

- repo / project names (`eog`, `agent-collections`)
- in-repo relative paths (`portal/`, `docs/context/eog/`)
- env placeholders (`$AGENT_COLLECTIONS_HOME`, `${env:AGENT_COLLECTIONS_HOME}`)

Local absolute paths belong only in private notes / terminal sessions, never in git-tracked content.

#### Area isolation reality (critical)

Installer applied framework **`area-fullstack.yaml`**:

```yaml
include:
  - apps/web/**
  - apps/api/**
  - packages/**
  - docs/**
  - scripts/**
exclude:
  - charts/**
  - "**/node_modules/**"
```

`apply-area-ignore.mjs` writes **only `exclude:`** patterns into ignore files. On EOG that yielded effectively:

- area-scope ignore: `charts/**`, `**/node_modules/**`
- **Not excluded:** `portal-nginx`, `cms-nginx`, `mariadb`, `elasticsearch`, `maildev`, `load-test`, `swarm-data-handbook*`, other heavy infra siblings

EOG actual app trees are **`portal/`** and **`cms/`** — abstract `apps/web` / `apps/api` includes do **not** map automatically. Per Q7 / migration guide, mapping must be a **consumer-owned overlay** (never hardcode `portal`/`cms` into framework `adapters/profiles/*.yaml`).

## Gap Analysis

### Question 1
#### Vendor mode for the remainder of the pilot: stay `local` or switch to `--vendor submodule`?
**Answer (2026-08-07):** **OK — local through Q5.** Keep `vendorMode: local` for the pilot session window; schedule **submodule + SemVer pin** before calling the install “team-ready.” Team default in runbook remains submodule.

### Question 2
#### Where should consumer ignore overlay live, and how deep?
**Design (unchanged):** overlay is **EOG-owned** in `.cursorignore` / `.claudeignore` (optional notes in EOG `docs/context/`). **Never** put `portal` / `cms` into framework `adapters/profiles/*.yaml`.

**What “depth” means — two independent layers:**

| Layer | What you exclude | Effect |
|-------|------------------|--------|
| **A — Heavy infra only** | `*-nginx/**`, `mariadb/**`, `elasticsearch/**`, `maildev/**`, `load-test/**`, handbooks, `charts/**`, … | Cuts noise from infra siblings. **Both** `portal/` and `cms/` stay visible in every Cursor/Claude session. |
| **B — Cross-area (FE ↔ BE)** | Additionally: FE sessions ignore `cms/**`; BE sessions ignore `portal/**` | Stronger isolation for Q5 “no collisions” AC, but needs **two ignore strategies** (or area-specific docs / session discipline), because one shared `.cursorignore` cannot be “portal-only” and “cms-only” at once without tooling tricks. |

**Today after install:** only framework `charts/**` (+ `node_modules`) landed in area-scope — so most EOG infra is still indexable. Layer A is the minimum to match `docs/context/eog/README.md`. Layer B is optional and harder in a single monorepo root install.

**Answer (2026-08-07):** **2a — Layer A only (heavy infra).** EOG consumer ignore overlay excludes infra siblings; `portal/` and `cms/` remain visible together. No hard FE↔BE ignore split in this pilot.

**DELTA (2026-08-07, human correction):** **2a overlay reverted.** `charts/`, `earth-care-handbook/`, and `swarm-data-handbook/` are **active product applications**, not disposable infra. Pilot requires broad monorepo indexing for Cursor. Consumer `# eog-pilot-overlay` removed; area-scope block must **not** exclude `charts/**` (override framework default after sync).

### Question 6
#### Should framework area manifests grow richer default excludes for “heavy infra”?
**What this asks:** should `adapters/profiles/area-*.yaml` in **agent-collections** gain more default `exclude:` entries so *every* consumer gets them from the installer — instead of (or in addition to) EOG writing its own ignore overlay?

| Option | Meaning | Pros | Cons |
|--------|---------|------|------|
| **6a — No (recommended for DHI-542)** | Keep framework abstract + thin (`charts/**`, `node_modules`). EOG adds consumer overlay. | Respects Q7 (“no client folder names in framework”); fastest pilot path | Each monorepo repeats overlay work |
| **6b — Yes, generic only** | Framework adds **vendor-neutral** patterns only (e.g. `**/charts/**`, maybe `**/*-nginx/**` if accepted as generic) | Helps many consumers | Risk of over-excluding odd layouts; still **must not** add `portal`/`cms`/`mariadb` EOG-specific names |
| **6c — Yes, EOG-shaped** | Put EOG tree names into framework profiles | Convenient for one client | **Forbidden** by isolation / Q7 policy |

**Answer (2026-08-07):** **6a — No framework YAML expansion for this story.** Keep `area-*.yaml` thin; ship heavy-infra excludes only as **EOG consumer overlay**. Optional **6b** may be a separate framework backlog later; **6c** rejected.
