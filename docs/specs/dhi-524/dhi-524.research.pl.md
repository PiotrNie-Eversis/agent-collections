**User story:** Jako frontend developer używający Cursor chcę mieć pliki `.cursor/rules/*.mdc` generowane z core, żeby mieć te same standardy co dziś bez utrzymywania zduplikowanych reguł.

## Wpływ biznesowy

Pierwszy **shipped** generator Work Stream 2: domyka ścieżkę „core SSOT → Cursor native”. Odblokowuje self-contained bootstrap (DHI-533), sync tooling (DHI-527), izolację globs (DHI-528–530 zależne od adapterów), instalator/wizard (5.x) oraz pilota EOG (frontend na Cursor). Bez tego repo nadal zależy od symlinków do `cursor-collections`.

## Kryteria akceptacji (z Jira)

1. **Generacja:** GIVEN core rules z zakresem domenowym WHEN adapter Cursor działa THEN powstają `.cursor/rules/*.mdc` z odpowiednim front matter (`globs` / `description` / `alwaysApply` wg mapy)
2. **Równoważność zachowania:** GIVEN wygenerowane reguły WHEN załadowane w Cursor THEN orchestration, code quality i **project-stack customization** zachowują się równoważnie do legacy dla projektu referencyjnego
3. **Re-run:** GIVEN aktualizacja reguły core WHEN adapter odpala się ponownie THEN reguły Cursor aktualizują się **bez** ręcznej edycji wygenerowanych plików
4. Dziedziczone AC SDD (folder spec, research → plan → implement → review → Fine)

## Gap Analysis

### Pytanie 1
#### Jaki **runtime / język** ma mieć generator Cursor w tej story?
**Opcje:**  
**A)** Node.js (np. `adapters/cursor/generate.mjs`) + minimalny sposób uruchomienia (`node …` lub mały `package.json` tylko pod adapter)  
**B)** Czysty bash  
**C)** Python  
**D)** W 524 tylko `rule-map.yaml` + przykładowe ręczne/wygenerowane `.mdc`; pełny generator w **DHI-527**  

**Wyjaśnienie:** AC wymaga *re-run* bez ręcznej edycji — to implikuje prawdziwy generator, nie jednorazowy commit `.mdc` (D słabo spełnia AC #3 i Technical Notes). Bash (B) radzi sobie ze złożeniem front matter + body, ale YAML + escapowanie + idempotencja szybko robi się kruche. Python (C) OK, ale w ekosystemie Cursor/Agent Collections Node jest naturalniejszy i bliższy przyszłemu toolingowi (MCP, installer). A = jeden plik `.mjs` + opcjonalnie zero deps (`node:fs`, prosty YAML parser ręczny lub `yaml` jeśli zaakceptujemy jedną zależność).  

**Rekomendacja:** **A** (Node `.mjs`, zero lub jedna lekka zależność). Unikać D — przenosi generator do 527 i łamie intencję Story 2.2.

**Odpowiedź (zatwierdzona 2026-08-05):** **A**

### Pytanie 2
#### Jaki **zakres wpisów** w pierwszym `rule-map.yaml`?
**Opcje:**  
**A)** Tylko odpowiedniki legacy framework (5 reguł: agent-core, testing-and-terminal, accessibility, engineering-manager, code-reviewer)  
**B)** Wszystkie 11 plików treści w `.ai/rules/**/*.md` (w tym seedy + SDD + fine-handoff)  
**C)** Legacy-equivalent (A) **plus** nowe orchestration (`fine-handoff`, `spec-driven-development`); seedy domain (backend/devops/shared-types/architecture-design) **później**  

**Wyjaśnienie:** A minimalizuje ryzyko i 1:1 z tym, co dziś widać w Cursor przez symlinki (minus BA). B maksymalizuje pokrycie core, ale seedy są cienkie i bez precedensu globs — łatwo o złe opakowanie (always-on za dużo / globs zgadywane). C domyka lukę orchestration (SDD + Fine są kluczowe w Delivery Standard), bez forsowania niepewnych globs dla seedów backend/devops.  

**Rekomendacja:** **C**. A jest zbyt wąskie względem aktualnego core orchestration; B za szerokie na pierwszy generator.

**Odpowiedź (zatwierdzona 2026-08-05):** **C**

### Pytanie 3
#### Co z **BA Docs** planner/writer (są w legacy `.mdc`, **brak** w `.ai/rules` — deferred DHI-519)?
**Opcje:**  
**A)** Poza DHI-524 — nie generować; usunąć symlinki BA przy przejściu na generowane rules (BA tylko jako skills/prompts w `.ai/`)  
**B)** Tymczasowo **zostawić symlinki** tylko dla BA do `cursor-collections`  
**C)** Dodać cienkie reguły core BA w tej story i zmapować je  

**Wyjaśnienie:** C rozszerza zakres 524 o ekstrakcję contentu (to był świadomy defer DHI-519) — scope creep. A jest czyste architektonicznie (adapter emituje tylko to, co jest w core), ale usuwa attachable BA rules z Cursor UX do czasu osobnej story. B utrzymuje hybrydę (wygenerowane + 2 symlinki) — brzydkie, ale zero regresji BA i zero nowego contentu w `.ai/`. Skills/prompts BA już są w `.ai/` — reguły roli to tylko cienkie opakowanie attach.  

**Rekomendacja:** **B** na MVP 524 (zachować symlinki BA), z komentarzem w README adaptera „temporary until BA core rules”. Alternatywa akceptowalna: **A**, jeśli świadomie akceptujesz utratę `@` BA rules do osobnego ticketa.

**Odpowiedź (zatwierdzona 2026-08-05):** **B**
