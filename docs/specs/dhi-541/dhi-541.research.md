## Business Impact

Root README is the **first document** most people open after cloning or browsing the repo. Today it reads as an engineer/maintainer reference (SSOT, SemVer, vendor modes, upgrade contract) before explaining *what the product does* or *how a newcomer starts*.

Cursor Collections README demonstrates a **human-first documentation UX**: hero → plain-language value → lifecycle map → worked examples with review/approve cues → quick start → deeper catalogs. Adopting that pattern for Agent Collections improves:

- Time-to-first-understanding for PMs, BAs, new engineers, and CTOs
- Clarity that this is a **vendor-neutral** framework (not “Cursor-only”) while keeping Cursor users oriented
- Consistency with the docs site tone (`website/docs/getting-started/`, workflow overview) without duplicating the entire encyclopedia into README

Accuracy of Agent Collections–specific facts (env vars, installer, adapters, MVP limits) must not regress.

### Codebase

#### Pattern source: cursor-collections README (UX structure)

Observed section order and UX techniques (names approximate):

| # | Section pattern | UX job |
|---|-----------------|--------|
| 1 | Centered hero (name + one-liner + lifecycle tagline + maintainer) | Brand + “what is this” in one screen |
| 2 | What this repository provides (by lifecycle phase: Rules / Prompts / Skills) | Mental model before install |
| 3 | Prerequisites (short) | Reduce false starts |
| 4 | Supported workflows + phase prose | Plain-language SDLC |
| 5 | Worked examples (ASCII with ↳ Review / ✅ Approve) | Non-technical path through gates |
| 6 | Human judgment callout | Sets expectations (drafts need approval) |
| 7 | Quick start (numbered, do-this-now) | Actionable first hour |
| 8 | Public prompts at a glance (table) | “What do I attach?” |
| 9 | Agents roster by phase (Focus / Invoke) | Role vocabulary for newcomers |
| 10 | MCP setup (Option 1 user / Option 2 workspace) | Guided integration |
| 11 | Using in another repository (clone → export → script) | Consumer onboarding |
| 12 | Related documentation table | Deep links without stuffing README |

Recurring UX principles:

1. **Front-load outcome language**, not architecture jargon.
2. **Phase metaphors** (Ideate / Implement / Review) before folder trees.
3. **Human gates** called out explicitly (Review → Approve).
4. **Examples before catalogs** (walkthroughs before full agent list).
5. **Progressive disclosure** — README = map; website/docs = encyclopedia.
6. Light emoji/section icons for scanability (optional in Agent Collections — match brand taste; do not overdo).

## Proposed README information architecture (for plan)

Recommended order (adapt cursor-collections UX to Agent Collections facts):

1. **Hero** — name, one plain sentence, Delivery Standard tagline, Eversis
2. **What this is / who it is for** — 3–5 bullets for BA, engineer, tech lead (non-jargon)

7. **Install into your project** — script + vendor modes table (keep accuracy; softer intro sentence)
