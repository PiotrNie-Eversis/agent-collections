# Agent Collections — framework reference

Authoritative short guide for **Agent Collections**: a vendor-neutral multi-agent core (`.ai/`) with adapters, installer, and MCP. Consumer documentation is written in **English**.

**Delivery standard:** Ideate → Research → Plan → Implement → Review → Fine.

Repo source: [`documentation/agent-collection.md`](https://gitlab3.eversis.com/eversis-ai/agent-collections/-/blob/master/documentation/agent-collection.md).

:::info Hosting
This site builds locally (`npm run build` in `website/`). **Public hosting is deferred** — there is no production docs URL in MVP.
:::

## Model

The repo splits into five top-level concerns: canonical content, tool packaging, the MCP server, the installer, and shared templates.

```text
.ai/          SSOT — rules, skills, prompts
adapters/     Cursor / Claude / OpenCode packaging + sync
mcp/          eversis-collections-mcp → .ai/skills via AGENT_COLLECTIONS_HOME,
              + domain context (docs/context/) via a second, independent volume
scripts/      setup-agent-collections.sh
templates/    AGENTS / stack / mcp seeds
```

Three terms recur throughout these docs — this table is the quick lookup; see the [Glossary](./reference/glossary) for plain-language versions.

| Concept      | Definition                                                  |
| ------------ | ----------------------------------------------------------- |
| **Core**     | Canonical Markdown under `.ai/`                             |
| **Adapter**  | Tool packaging that consumes core (does not own SSOT text)  |
| **Consumer** | Application repo that installs via local / submodule / copy |

Related product **Cursor Collections** is a separate Cursor distribution channel. Dual-channel **code** is allowed; **documentation channels stay fully separate** (no shared docs portal). See [Migration](./advanced/migration-from-cursor-collections).

## Install and env

The canonical install path is the [Start here](./getting-started/start-here) checklist. This snippet is the equivalent commands for readers who already know the framework and just need the exact invocation:

```bash
export AGENT_COLLECTIONS_HOME=/path/to/agent-collections
bash "$AGENT_COLLECTIONS_HOME/scripts/setup-agent-collections.sh" \
  --build-mcp --non-interactive \
  --agents=cursor,claude \
  --mcp-servers=eversis-collections \
  --profile=fullstack
```

- Env for skills MCP: **`AGENT_COLLECTIONS_HOME`** (not `CURSOR_COLLECTIONS_HOME`).
- Selection: `.agent-collections/install-selection.json`.

Details: [Installation](./getting-started/installation), [MCP setup](./getting-started/mcp-setup).

## Agents and prompts

Each lifecycle phase has one primary entry-point prompt:

| Phase       | Primary prompt id           |
| ----------- | --------------------------- |
| Ideate      | `eversis-analyze-materials` |
| Implement   | `eversis-implement`         |
| Review      | `eversis-review`            |
| Review (UI) | `eversis-review-ui`         |

Load prompts by stable id under `.ai/prompts/`. Optional Cursor `@` attach when surfaced, or `/eversis-*` once `.cursor/commands/` (Cursor) or `.claude/commands/` (Claude Code) was generated by the respective adapter.

## Skills (MCP)

Skills are the reusable procedures an agent loads on demand rather than keeping in its base instructions.

Skills live under `.ai/skills/eversis-*/`. Prefer MCP server **`eversis-collections`** (`eversis_skills_list` / `eversis_skills_get`). Respect the consumer **project stack** skills policy. Includes 4 domain-context skills: `eversis-add-domain-knowledge`, `eversis-promote-domain-knowledge`, `eversis-import-confluence-knowledge`, `eversis-audit-domain-knowledge`.

Both adapters mirror skill packages under `.cursor/skills/eversis-*` and `.claude/skills/eversis-*` (framework sync / installer) for load-by-path or `@` attach. Prefer MCP for discovery; do **not** register `.cursor/skills` as Cursor **Agent Skills** UI.

The same MCP server also exposes a separate tool group, `eversis_context_*`, for reading and syncing **domain context** — see [Domain Context (SSOT)](./domain-context) and the [full tool inventory](./reference/integrations/eversis-collections#domain-context).

## Multi-agent and isolation

Each supported tool packages the same core content differently:

- **Cursor** — generated `.cursor/rules/*.mdc` + `.cursor/commands/*.md`; skills via MCP (preferred) plus `.cursor/skills/` mirror for file/`@` attach (not Agent Skills UI).
- **Claude Code** — root `CLAUDE.md` + `.claude/rules/*.md` (glob-scoped) + `.claude/commands/*.md`; skills **natively** via `.claude/skills/` (linked by the installer). Project-specific notes go in `.claude/CLAUDE.md` (seeded once, never overwritten) — Claude Code does not auto-read `AGENTS.md`.
- **OpenCode** — placeholder only.

Cross-tool ignore + area profiles: [Isolation](./isolation). Abstract layout uses `apps/web` / `apps/api`; consumers map local trees via overlay (not framework profile hardcoding).
