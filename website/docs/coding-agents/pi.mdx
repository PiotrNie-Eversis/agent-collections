# Agent Collections in Pi

Agent Collections gives Pi the process: the gates, the role rules and the skills. Pi gives Agent Collections the runtime: commands, extensions, tools and MCP.

## The delivery cycle

Each stage shows what the process does and which Pi tools do the work. Quick Flow can skip Research and Plan.

Research runs in the same session with eversis-orchestrating-implementation, and you approve it. The plan is written with eversis-creating-implementation-plans, the Plan Reviewer checks it in the same session before you see it, and you approve the plan. Implement uses edit, write and bash, with eversis-context-budget. Review runs in a separate Pi session through the eversis_independent_review tool: a BLOCKER goes back to Implement, PASS goes on to Fine. Fine uses eversis-fine-handoff and the atlassian MCP, and you approve publishing."

### Tools at each stage

| Stage | Kind | Tool | Note |
| --- | --- | --- | --- |
| Ideate | Process | Agent Collections | Turns workshop materials into Jira-ready stories. |
| Ideate | Command | `/eversis-analyze-materials` | Optional. Starts from workshop materials. |
| Start | Process | Agent Collections | Prints the Implement readiness block and picks Quick or Full. |
| Start | Command | `/eversis-implement <ticket>` | — |
| Start | Extension | `eversis-process-rules` | Adds five rule skills and shows a notice. |
| Start | File | `.pi/APPEND_SYSTEM.md` | The small core, always on. |
| Research | Process | Agent Collections | Gathers context and writes `*.research.md`. You approve research before Plan starts. |
| Research | Skill | `eversis-orchestrating-implementation` | Pi has no sub-agents, so this runs in the same session. |
| Research | MCP | `eversis-collections`, `atlassian` | Skills, domain context and the ticket. |
| Plan | Process | Agent Collections | Writes `*.plan.md` with phases and acceptance checks. |
| Plan | Skill | `eversis-creating-implementation-plans` | — |
| Plan | Extension | `eversis-process-rules` | Saves `.pi/eversis-state/active-plan.json`, so a new session starts with the rules on. |
| Plan review | Process | Agent Collections | Checks the plan before you see it. Only a BLOCKER sends it back to Plan, at most three rounds. You approve the plan before Implement starts. |
| Plan review | Role | Plan Reviewer | Runs the `eversis-review-plan` prompt and writes `*.plan-review.md`. Pi has no sub-agents, so this runs in the same session. |
| Implement | Process | Agent Collections | Changes the code, then runs lint, typecheck and tests. |
| Implement | Tools | edit, write, bash | — |
| Implement | Skill | `.pi/skills/eversis-*` | Domain skills the plan calls for. |
| Implement | Extension | `eversis-context-budget` | Compacts once at 50% and resumes the task. |
| Review | Process | Agent Collections | Reports PASS, BLOCKER or SUGGESTION against the plan. BLOCKER goes back to Implement; PASS goes on to Fine. |
| Review | Extension | `eversis-review` | Runs `/eversis-review` automatically in a separate, clean Pi session via the `eversis_independent_review` tool. |
| Review | Command | `/new, then /eversis-review <ticket>` | Fallback when the separate session cannot start. |
| Review | Skill | `eversis-rule-code-reviewer` | — |
| Fine | Process | Agent Collections | Writes the QA comment draft in the same turn. You approve publishing. |
| Fine | Skill | `eversis-fine-handoff` | — |
| Fine | MCP | `atlassian` | Posts the comment only after approval. |

## When the process rules turn on

Pi loads the full process rules only when a session needs them. Every session gets a small always-on core. The extension `eversis-process-rules` adds the rest.

<PeleDiagram
  id="pi-rules-flow"
  source={rulesFlow}
  label="At session start, the rules turn on if the session has a saved command or there is an active plan. On each message, an eversis command turns the rules on. With the rules on, the request carries the core and five rule skills, and all skills are listed. With the rules off, it carries the core only and eversis skills are hidden. When Pi edits a plan in docs/specs, the path is saved and applies from the next session."
/>

The five rule skills are `eversis-rule-agent-core`, `eversis-rule-testing-and-terminal`, `eversis-rule-accessibility`, `eversis-rule-engineering-manager` and `eversis-rule-spec-driven-development`. Other role skills, such as `eversis-rule-code-reviewer`, load on demand.

| Trigger | Stays on for | Ends when |
| --- | --- | --- |
| An `eversis-*` command | The rest of that session, including `--continue`, `/reload` and compaction | A new session starts |
| An active plan | Each new session | The plan has no open checkbox, or its file is absent, for example on another git branch |

- A plan edit does not change the running session. It applies from the next session.
- A plan counts only if Pi edited it and the edit succeeded.
- A command sent while the agent is busy starts the rules with the next run, and the notice says so.

## What the model receives

Measured on a full install with Pi 1.5.0:

| Request | System prompt |
| --- | --- |
| Before on-demand rules, every request | 42,902 characters |
| No command | 4,556 characters |
| First request after a command | 57,908 characters |

Your numbers will be higher if the project has a customised project-stack overlay or a long `AGENTS.md`, because both are always on.

For setup, see [Installation](../getting-started/installation.mdx). The full behaviour is in `adapters/pi/README.md`.
